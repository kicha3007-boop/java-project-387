# 4. Хранение в памяти и границы тестов

Статус: принято

## Решение

- Данные (типы встреч, бронирования) хранятся в памяти процесса; при старте есть два типа встреч
  по умолчанию. Авторизации и нескольких владельцев в проекте нет, базу данных добавим, когда
  понадобится переживать перезапуск.
- Тесты на трёх границах:
  1. правила слотов — чистые функции `server/src/domain/slots.ts` (vitest);
  2. HTTP API по контракту — `fastify.inject` (vitest): коды, поля, конфликт между типами встреч;
  3. сквозной сценарий в браузере — Playwright поверх собранного приложения: запись гостя,
     подтверждение, встреча у владельца, конфликт слота.

## Последствия

Перезапуск сервиса очищает записи — ограничение учебного сервиса, указано в README.
