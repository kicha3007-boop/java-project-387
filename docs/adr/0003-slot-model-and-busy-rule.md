# 3. Модель слотов и правило занятости

Статус: принято

## Решение

- Время хранится и показывается в UTC; гость и владелец видят одно и то же.
- Окно записи — 14 дней с текущей даты, рабочие часы 09:00–18:00, сетка 30 минут.
- Длительность типа встречи кратна 30 минутам (30–240). Слот — интервал длительностью типа
  встречи, начало на сетке, конец не позже конца рабочего дня, начало в будущем.
- Занятость общая для всех типов встреч: бронирование занимает интервал `[start, start + длительность)`,
  слот любого типа, пересекающийся с ним, не предлагается.
- Правила проверяются на сервере при `POST /api/bookings`: начало вне сетки/окна — `422`,
  пересечение с занятостью — `409 slot_unavailable`. Интерфейс только показывает ответ.

## Последствия

Прямой запрос в API не создаст вторую запись на занятое время; гость, у которого слот заняли,
пока он заполнял форму, получает понятное сообщение и обновлённый список слотов.
